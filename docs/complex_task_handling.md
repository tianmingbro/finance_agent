# 复杂任务拆分与汇总

**版本**：V1.0  
**日期**：第8周 Day52  

## 概述

Orchestrator Agent 支持将用户的复合指令（如“查一下LPR并评估答案是否准确”）自动解析为多个子任务，按照依赖关系串行或并发执行，并将各子任务的结果汇总后一次性返回。该能力使系统能够处理多步骤的金融咨询请求，提升交互效率。

## 意图解析算法

### 解析策略
当前采用**规则匹配**方法解析复合意图，原因：
- 金融领域指令模式较为固定，规则可覆盖80%以上场景。
- 避免额外LLM调用延迟和不确定性。
- 规则透明、易调试、易扩展。

### 支持的意图模式

| 模式 | 触发关键词 | 生成子任务 | 示例 |
|------|------------|-------------|------|
| **串行链** | 同时包含“查”“评测”/“评估” | 1. RAG 问答<br>2. Eval 评测（依赖问答结果） | `查一下资本充足率并告诉我回答是否准确` |
| **并行双问** | “各是多少”、“和…多少” | 两个并发的 RAG 问答子任务 | `资本充足率和存款保险上限各是多少？` |
| **条件汇总** | “评测…如果…就重新回答” | 1. Eval 评测<br>2. RAG 问答（条件依赖，仅当评测分数低于阈值） | `评测这个回答：核心资本充足率是8%，如果低于0.7就重新回答` |

### 解析流程

1. 对输入文本进行预处理（去除多余空格）。
2. 依次匹配模式规则，提取关键信息（问题、答案、阈值）。
3. 构造 `Subtask` 对象列表，每个 `Subtask` 包含：
   - `type`：`"rag"` 或 `"eval"`
   - `query`：问题文本
   - `answer`：待评测的答案（如有）
   - `depends_on`：依赖的子任务索引列表
   - `condition`：条件表达式（可选）
4. 若无法匹配任何模式，返回空列表，Orchestrator 退回到简单路由（单一问答或评测）。

## 子任务编排流程

### 执行引擎 `execute_subtasks`

1. **初始化**：根据子任务总数创建结果槽位，记录已完成子任务集合。
2. **断点续查**：检查会话 `session_store` 中是否已存在相同子任务的成功结果，若存在则直接复用，避免重复执行。
3. **依赖等待**：如果子任务有 `depends_on`，则循环等待直到所有依赖完成。
4. **上下文构建**：
   - 汇总依赖子任务的结果，提取其中的 `context` 字段合并。
   - 若当前子任务为评测且缺少 `answer`，自动从依赖的 RAG 结果中提取答案。
5. **带重试的调用**：
   - 每个子任务最多尝试 `MAX_RETRIES + 1` 次（默认 MAX_RETRIES=2）。
   - 单次调用设置超时 `SUB_TIMEOUT` 秒（默认 30s）。
   - 失败时根据错误类型记录日志，并在重试间隔 `RETRY_DELAY` 秒后重试。
6. **结果缓存**：子任务成功或失败后，将结果按 `subtask_id` 存入会话的 `subtasks` 字段，支持后续断点续查。
7. **汇总**：
   - 所有子任务执行完毕后，遍历结果：
     - 成功的子任务将其 `artifacts` 追加到最终 Task。
     - 失败或跳过的子任务附加错误信息。
   - 最终 Task 状态：若存在失败子任务则为 `"partial"`，否则为 `"completed"`。

### 并发与串行控制

- 无依赖的子任务立即创建 `asyncio.Task` 并发执行。
- 有依赖的子任务同样创建 `asyncio.Task`，但其内部会先等待依赖完成再执行实际操作，从而实现正确的执行顺序。

### 流程示例（串行链）

```mermaid
sequenceDiagram
    participant User
    participant Orchestrator
    participant RAG
    participant Eval

    User->>Orchestrator: 查一下资本充足率并评估答案是否准确
    Orchestrator->>Orchestrator: 解析为子任务[rag, eval(dep=0)]
    Orchestrator->>RAG: 子任务0 (rag)
    RAG-->>Orchestrator: 答案+上下文
    Orchestrator->>Eval: 子任务1 (eval, 上下文含答案)
    Eval-->>Orchestrator: 评测分数
    Orchestrator-->>User: 答案 + 评测结果

配置参数
参数	默认值	说明
MAX_RETRIES	2	子任务失败后的最大重试次数
RETRY_DELAY	1.0	重试前等待秒数
SUB_TIMEOUT	30	单个子任务 HTTP 调用超时秒数
SESSION_TTL	300	会话存储过期时间（秒），影响子任务缓存的寿命

参数可在 agents/orchestrator.py 顶部修改。
断点续查与幂等性

    每个子任务的结果以 subtask_id（格式 {task_id}-{index}）为键存储在会话的 subtasks 字典中。

    当下次请求携带相同 session_id 且包含相同 task_id 和子任务索引时，Orchestrator 直接返回缓存结果，不会重复调用下游 Agent。

    会话 TTL 过期后缓存自动清除，保证数据新鲜度。

错误处理

    子任务超时：asyncio.wait_for 触发后，自动重试。若全部重试失败，将在最终结果中标记该子任务失败，并包含超时错误信息。

    下游 Agent 异常（HTTP 500/连接拒绝）：同样触发重试，最终失败时错误信息透传给用户。

    部分成功：Orchestrator 返回 status: "partial"，成功的子任务结果正常展示，失败的部分附带错误详情，不影响整体体验。
