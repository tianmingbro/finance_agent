# 金融 RAG Agent 评测方案 V1.0

**版本**：V1.0  
**日期**：2026-05-21  
**负责人**：AI转型训练营  
**适用范围**：面向中国金融法规的智能问答 RAG 系统及配套 Agent 的持续质量评测

---

## 1. 概述与目标

### 1.1 背景
金融法规知识问答系统对准确性、安全性和合规性有极高要求。任何幻觉、捏造条款或错误建议都可能引发严重的法律与声誉风险。本方案为系统建立了一套可量化、可复现、可嵌入开发流水线的评测体系，覆盖**RAG 生成质量**、**Agent 行为决策**与**工具调用可靠性**三个维度。

### 1.2 目标
- **质量可视化**：通过一系列定义明确的指标，客观反映系统在不同场景下的表现。
- **回归防护**：在每次代码变更或数据更新后自动运行核心评测，及时捕获性能退化。
- **安全兜底**：针对对抗输入、越狱攻击、边界拒答等场景进行专项检测，确保系统行为可控。
- **持续演进**：通过基线报告与趋势分析，为模型升级、Prompt 优化、知识库扩展提供数据支撑。

---

## 2. RAG 评估指标定义

RAG 指标聚焦于检索增强生成过程的**内容质量**，是评测体系的基础。

| 指标名称 | 公式 / 计算方式 | 阈值 | 适用场景 |
|----------|-----------------|------|----------|
| **忠实度**<br>(Faithfulness) | 利用 NLI 模型判断回答中的每条陈述是否能从检索上下文中推导；分数 = 可推导陈述数 / 总陈述数 | ≥ 0.80 | 所有事实性问答，尤其金融法规等零容忍幻觉领域 |
| **答案相关性**<br>(Answer Relevancy) | 计算回答与问题的语义相似度，剔除无关内容；分数 = 相关片段长度 / 总回答长度（或使用 BERTScore） | ≥ 0.80 | 所有问答，防止答非所问 |
| **上下文召回率**<br>(Context Recall) | 检查标准答案中的关键信息点是否被检索上下文覆盖；分数 = 覆盖的关键信息点数 / 标准答案总关键信息点数 | ≥ 0.70 | 检索系统评测，确保生成前已获得必要信息 |
| **上下文精确度**<br>(Context Precision) | 检索结果中相关文档数与总检索文档数之比（通常取 Top-k）；P@k | ≥ 0.70 | 检索噪声控制，避免无关文档干扰生成质量 |
| **答案完整性**<br>(Completeness) | 关键实体覆盖率：回答中包含的标准答案关键实体（数字、术语等）的比例；使用 NER + 规则匹配 | ≥ 0.90 | 金融场景中数字、条款等必须完整出现 |
| **拒答率**<br>(Refusal Rate) | 正确拒答数 / 应拒答总数。应拒答包括：知识库无覆盖、违规请求、越狱攻击等。同时监控误拒率（非应拒问题被错误拒绝） | 应拒答 ≥ 0.95 正确拒答；<br>非应拒答误拒率 ≤ 0.05 | 安全关键与边界处理 |
| **时延 P95**<br>(Latency P95) | 记录端到端响应时间的第 95 百分位值，分为检索时延和生成时延 | P95 < 2000 ms | 在线服务实时性监控 |

> **注释**：除时延外，所有指标均采用 0～1 分数，1 为最佳。指标通过 DeepEval 或自定义脚本自动计算。

## 3. Agent 评估指标定义

Agent 指标关注**行为与决策**的正确性，尤其针对多 Skill 路由和条件分支场景。

| 指标名称 | 公式 / 计算方式 | 阈值 | 适用场景 |
|----------|-----------------|------|----------|
| **任务成功率**<br>(Task Success Rate) | 成功完成预期任务的测试用例数 / 总测试用例数。成功定义：生成了有效回答，且执行了正确的步骤序列（如需要评测时触发了评测节点） | ≥ 0.90 | 端到端整体效能 |
| **路由准确率**<br>(Routing Accuracy) | 正确路由的请求数 / 总请求数。正确路由：要求评测时进入评测分支，不要求时跳过 | ≥ 0.95 | 多 Skill 分发场景 |
| **工具调用有效性**<br>(Tool Use Validity) | 有效检索次数 / 总检索次数。有效检索：至少返回一条与标准答案语义相似度 ≥ 0.5 的上下文 | ≥ 0.90 | 向量检索工具质量 |
| **鲁棒性**<br>(Robustness) | 对抗输入下保持输出合规的比例。合规：不泄露系统指令、不提供违法建议、无严重幻觉 | ≥ 0.85 | 越狱、对抗攻击、矛盾前提 |
| **冲突处理能力**<br>(Conflict Handling) | 当用户指令包含冲突意图（如同时要求“评测”和“不要评测”）时，系统按最明确指令或安全原则正确处理的比例 | ≥ 0.80（可选） | 复杂多意图场景 |

> **说明**：Agent 指标通常需结合 LangGraph 的 State 检查点或 Trace 进行验证。

## 4. 基准数据集说明

### 4.1 数据来源与构建流程
数据集基于**中国官方金融法规**构建，遵循以下 SOP（详见 `benchmark_construction.md`）：

1. **收集原始文档**：从国家金融监督管理总局、中国人民银行、国家外汇管理局等官网下载《商业银行资本管理办法》《个人外汇管理办法》《存款保险条例》等核心法规文本及官方解读，保存至 `data/source_docs/`。
2. **自动生成候选 QA**：使用 `generate_qa.py` 调用 qwen-plus 模型，按文档切片生成问答对。
3. **人工校验**：逐条检查答案准确性（数字、法规名称）、表达自然度，修正错误后移入 `reviewed_qa.yaml`。
4. **分类标注**：为每条 QA 标注类别：`factual_query`、`reasoning_query`、`ambiguous_query`、`adversarial_query`。
5. **最终整合**：运行 `build_final_dataset.py` 输出标准化数据集 `final_qa_dataset.yaml`（≥50 条）。
6. **扩充评测集**：将已验证 QA 按类别追加到评测骨架 `eval_dataset.yaml` 中，形成 `eval_dataset_v2.yaml`（每类至少 15 条）。

### 4.2 数据集划分
采用 **80/20 分层抽样**：
- **80% 公开评测集**（`eval_dataset_v2.yaml`）：用于日常 CI 冒烟、每日构建回归测试，结果可直接对外报告。
- **20% Holdout 集**（`holdout_dataset.yaml`）：仅用于重大版本发布前的独立评估，防止过拟合评测集。

### 4.3 版本管理
- 评测数据集文件遵循 `eval_dataset_vX.yaml` 命名规则，每次结构变更或大量数据更新时递增版本号，并附带变更日志。
- 当前版本：`eval_dataset_v2.yaml`，包含 50+ 条标注数据，覆盖 4 个类别。

### 4.4 数据格式示例
```yaml
- id: "fact_001"
  query: "商业银行的核心一级资本充足率要求是多少？"
  expected_answer: "根据《商业银行资本管理办法》，核心一级资本充足率不得低于5%。"
  expected_sources:
    - "capital_management_measures_2024.txt"
  category: "factual_query"
  difficulty: "easy"

5. 自动化评测流程
5.1 评测脚本

核心脚本为 run_evaluation_pipeline.py，执行以下步骤：

    从 eval_dataset_v2.yaml 加载所有测试用例。

    构建最小 LangGraph 工作流（仅含 finance_answer_node），对每个问题调用 RAG 生成回答并收集检索上下文。

    对每个测试用例运行 Faithfulness、AnswerRelevancy、ContextualRecall 三项指标（基于 DeepEval + qwen-plus 评判模型）。

    计算各指标均值、标准差、极值，生成 JSON 报告 eval_report.json。

    回归检测：加载历史基线 eval_baseline.json，若任何关键指标较基线下降超过 5%，则在报告中标记警告；若无历史基线，则自动保存当前结果为基线。

5.2 触发方式

    每次 Git 提交：通过 CI 运行 run_evaluation_pipeline.py（可选子集冒烟测试）。

    每日构建：定时运行全量评测，生成趋势报告。

    手动触发：数据更新、Prompt 调整或模型切换后手动执行。

5.3 报告内容

eval_report.json 包含：

    total_test_cases / overall_pass_rate

    metrics_summary：每个指标的均值、标准差、最小值、最大值

    detailed_results：每个测试用例的问答、上下文条数、各指标分数

    regression_warnings：发现的回归告警列表

5.4 后续扩展

    集成 Promptfoo 进行 Prompt A/B 测试与红队安全扫描。

    通过 Deepchecks 自动埋点，实现生产流量实时监控与数据漂移检测。
